# Transformers 기초 학습 노트

## 토크나이저

토크나이저는 입력 문장을 모델이 처리할 수 있는 토큰 조각으로 나눈다. 토큰은 단어 전체일 수도 있고, 단어의 일부나 문장부호일 수도 있다. 각 토큰은 어휘 사전에서 정수인 토큰 ID에 대응한다. 따라서 사람이 쓰는 문장은 먼저 토큰 ID의 수열로 바뀌며, 모델은 그 수열을 입력으로 받는다. 토큰화 방법과 어휘 사전이 달라지면 같은 문장도 서로 다른 ID 수열이 될 수 있다. 입력 길이와 생성 길이를 셀 때 문자 수가 아니라 토큰 수를 확인해야 하는 이유다.

## 인코더 전용 모델

BERT처럼 인코더만 사용하는 모델은 입력 문맥의 양쪽을 함께 살펴 각 토큰의 표현을 계산한다. 대표적인 사전 학습 방법은 문장 일부를 가린 뒤 원래 토큰을 맞히게 하는 마스킹 언어 모델링이다. 이런 양방향 문맥 표현은 문장 분류, 토큰 분류, 검색 임베딩 같은 이해 작업에 자주 쓰인다. 인코더 모델은 다음 토큰을 이어 쓰도록 설계된 생성 모델과 목적이 다르므로, 임의의 인코더 체크포인트를 텍스트 생성 API에 바로 연결할 수 있는 것은 아니다.

## 디코더 전용 인과 언어 모델

GPT 계열의 디코더 전용 모델은 앞에서 이미 나온 토큰을 바탕으로 다음 토큰의 확률을 계산한다. 학습과 생성 과정에서 뒤쪽 정답 토큰을 미리 보지 않도록 인과 어텐션 마스크를 적용한다. 추론할 때는 지금까지의 문맥에 다음 토큰 하나를 붙이고, 그 토큰을 새 문맥으로 삼아 반복한다. 이 방식으로 이어 쓰기, 대화, 요약과 코드 생성이 가능하다. Transformers에서는 이런 체크포인트를 보통 AutoModelForCausalLM으로 불러온다.

## 인코더-디코더 모델

T5처럼 인코더와 디코더를 함께 쓰는 모델은 입력 시퀀스를 인코딩한 뒤, 그 표현을 조건으로 출력 시퀀스를 생성한다. 입력과 출력의 길이가 달라도 사용할 수 있어 번역, 요약, 질의 응답처럼 한 텍스트를 다른 텍스트로 바꾸는 작업에 어울린다. 체크포인트가 어떤 구조를 사용하는지는 모델 카드와 config.json의 아키텍처 정보를 확인해야 한다. 모델 구조와 작업에 맞는 AutoModel 클래스를 선택해야 가중치와 출력 헤드가 올바르게 연결된다.

## 추론과 파인튜닝

추론은 저장된 모델 가중치를 읽어 입력에 대한 출력을 계산하는 단계이며, 보통 추론 중에는 가중치를 업데이트하지 않는다. 파인튜닝은 데이터셋과 손실 함수를 정하고 학습 단계를 반복해 가중치를 업데이트하는 과정이다. 전체 파라미터를 갱신하는 방식은 메모리와 저장 공간을 많이 쓸 수 있다. 학습과 추론은 목적과 실행 코드가 다르므로, 설정 파일에서도 추론용 생성 옵션과 학습용 optimizer·learning rate·epoch 설정을 구분하는 편이 좋다.

## LoRA 어댑터

LoRA는 기반 모델의 모든 파라미터를 다시 학습하는 대신 일부 선형 층에 작은 저랭크 어댑터를 붙여 학습하는 PEFT 방식이다. 기반 가중치를 고정하고 어댑터 파라미터를 학습하면 학습해야 할 파라미터 수와 별도로 저장할 결과 크기를 줄일 수 있다. 어댑터를 다시 쓸 때는 기반 모델 ID와 revision도 함께 기록해야 한다. 서로 다른 기반 모델이나 revision에 어댑터를 임의로 연결하면 같은 결과를 재현하지 못할 수 있다.

## RAG 평가

RAG는 질문과 가까운 문서 청크를 찾는 검색 단계와, 찾은 근거를 사용해 답을 작성하는 생성 단계로 나눌 수 있다. 검색이 잘못된 근거를 고르면 생성 모델이 그 사실을 알고 있어도 주어진 문맥만으로 답하기 어렵다. 검색 결과의 순위와 점수, 답변의 근거 인용 여부를 각각 살펴야 어느 단계의 설정을 고칠지 판단할 수 있다. 같은 질문과 문서를 고정해 모델·검색 설정을 비교하면 실험 사이의 차이를 더 쉽게 추적할 수 있다.
